# Spine 3.8.75 部件改图完整流程

## 当前样本的图片是什么

`editor_project/images/atlas_00/regions/*.png` 是普通带透明通道的 PNG，没有特殊的 Spine 图片编码。Spine 工程存储骨骼、插槽、附件、网格、动画及图片路径，PNG 仍是外部文件；移动工程时应整体移动 `editor_project`。

本程序的文件名前缀 `p00` 表示图集页，`i-1` 来自未指定序号的 atlas region index，属于防重名命名规则。不要凭相似缩略图或文件名把图片合并、删除。

本次只读检查“贝尔法斯特.改 魔改”的转换输出：2 页图集、114 个 region、247 对 region 矩形有重叠。生成工程的 112 个视觉附件引用全部能找到 PNG。`faB_1` 等图片中大量非透明像素位于对应网格三角形之外。这与多边形打包的机制一致：不同部件的网格轮廓可以相互嵌套，但其外接矩形重叠。因此矩形拆图会夹带邻图，不代表 Spine 会把整张矩形全部画到角色上。

当前导出器恢复旋转、裁边前尺寸和透明度，保留原始 UV，但没有按所有使用者的网格并集清除矩形中的邻图。因此这些图片**不是原作者 PSD 图层的完整恢复**。没有原工程上下文时，官方也指出拆图可能带上网格轮廓外的邻图。[官方 CLI 拆图说明](https://en.esotericsoftware.com/spine-command-line-interface#Unpack)

不要直接根据某一个附件的网格删除所有外围像素：一张图片可能被多个附件共享，纹理过滤也需要边缘余量。仅改色时保留其他区域更稳妥。放大或重建网格时，原本网格外的邻图可能进入可见区域。

## 可以在 Spine 中修改什么

Spine Pro 可以选中部件，调整位置、网格、骨骼权重、皮肤和动画；像素绘画仍在 Photoshop、Krita 等图像编辑器中完成。Spine 监视图片文件变化，回到 Spine 后可看到修改。[官方 Images 文档](https://us.esotericsoftware.com/spine-images)

这与 Live2D 的 UV 覆盖 PSD 不同：这里直接编辑附件引用的独立图片，再由 Spine 重新导出、打包；不是把人物截图投影回原图集，也不会自动保持旧 atlas 的区域坐标。

## 推荐流程：改颜色、纹理、局部细节

1. **复制整个 `editor_project` 目录**作为编辑版本，用 Spine **3.8.75** 打开其中的 `skeleton_0.spine`，不要再次导入外层 `model0.json`。确认树中的 Images/图片 路径指向 `./images/`。
2. **进入设置模式选中附件**。在画布点击目标部件，或在层级树展开骨骼/插槽，选中具体附件。注意当前皮肤与动画可能切换附件；修改哪个附件，就核对哪个附件的 `Path`。
3. **定位实际图片**。例如附件 Path 为 `atlas_00/regions/p00_fasi_1_i-1`，文件就是 `images/atlas_00/regions/p00_fasi_1_i-1.png`。如果 Path 为空，才按附件名查找。多个附件可引用同一路径，一处修改会影响所有使用位置。[官方图片查找规则](https://us.esotericsoftware.com/spine-images#Image-file-lookup)
4. **用图像编辑器打开 PNG**。可另存一个 PSD 用于保留原图、绘画层与遮罩，但供 Spine 使用的仍是原路径 PNG。显示透明网格，避免把透明背景误看成白底。对于夹带邻图的图片，仅编辑目标部件范围，不移动、裁剪或删除邻图。
5. **保持画布尺寸和内容坐标不变**。改色、补细节可直接进行；保存为同名 RGBA PNG，保留透明通道。不要导出白底 JPEG，不要把所有部件另存成同一个名字。
6. **回到 Spine 检查结果**。通常会自动刷新；若未更新，选中 Images/图片 节点使用 Refresh/刷新，必要时重新打开工程。检查设置姿态以及相关动画的多个时间点，尤其是变形、遮挡和附件切换处。
7. **保存 `.spine` 工程**。图片修改保存在 PNG，骨骼/动画修改保存在工程；二者都要备份。如果改动范围超出原网格，新增像素不会自动显示，需要在 Spine 中调整网格、权重和相关变形动画。改变图片尺寸也可能需要调整 UV，不属于简单换图。[官方网格文档](https://us.esotericsoftware.com/spine-meshes)
8. **导出到新的目录**。在 Spine 的 Export 中选择目标运行时需要的 JSON 或 Binary，并启用纹理打包，得到配套骨骼数据、`.atlas`、PNG 页。保持目标程序所需的版本、缩放、PMA 等选项一致；不要只把新 PNG 页面塞进旧 atlas。然后用本程序预览新的配套资源，检查皮肤和动作。

原资源是 4.0.37，当前编辑副本为 3.8.75；从 3.8.75 导出后仍应按 3.8 数据使用。若要放回原资源包，还需确认宿主能加载该版本，并更新其骨骼、图集和贴图引用。单独改版本字符串不能解决运行时兼容。本文流程不承诺跨版本转换无损恢复作者工程。

## 像 Live2D 那样做 PSD 是否有必要

只改一个部件：PNG → 图像编辑器中的分层 PSD → 同名 PNG → Spine 刷新，足够直接。

想在完整人物姿态上绘画：需要额外的姿态到网格/UV 回投影流程。把渲染画面保存为 PSD，不等于能把任意绘画准确写回这些附件。本程序目前没有提供这种 Spine 姿态 PSD 回写。也不要把新版 Spine 的 PSD 导入说明直接当成 3.8.75 已验证功能。

本次验证了本地图片引用、区域重叠和网格外像素；以上编辑步骤依据官方文档整理，未声称已经在编辑器中人工完成整个改图与导出流程。

## 复核当前样本

```powershell
pixi run python scripts/inspect_spine_editor_images.py "runtime/output/spine/贝尔法斯特.改 魔改/skeleton_0_to_3.8.75_json" --report runtime/validation/spine-image-audit.json
```

该命令只读源文件，诊断报告写入指定位置，不修改图片或工程。统计的网格外像素包含过滤边缘，不能直接当作可安全擦除的掩码。
